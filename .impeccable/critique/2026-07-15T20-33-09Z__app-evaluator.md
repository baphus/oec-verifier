## What's Working

1. **Keyboard shortcut system** — V/R/Esc on DecisionControls, → for next-pending navigation, all properly guarded against input focus. The hint text ("Press V to verify · R to reject" / "Press → to skip to next pending") makes them discoverable without cluttering the UI. This is genuine power-user efficiency.

2. **StatusHelp tooltips** — Focusable `<Info>` icon with `aria-label`, `title` for native browser tooltip, and CSS hover/focus visual tooltip. Covers all 4 statuses with concise, accurate descriptions. Accessible, keyboard-reachable, non-intrusive. A model for lightweight contextual help.

3. **Card consolidation** — The 5→3 card merge on the detail page (Personal absorbed Address, Employment absorbed Timeline) reduced visual noise without losing any data. The `border-t` separator for record dates inside Employment is a subtle, effective hierarchy cue.

## Priority Issues

**[P2] StatusHelp descriptions are static and incomplete**
The `descriptions` map in `StatusHelp.tsx` covers pending/verified/rejected/revoked but not all possible states (e.g., "expired", "issued" if they appear in the data). Also, the descriptions are hardcoded strings — if status semantics change, they must be updated in two places (the component and the backend).
*Fix*: Derive descriptions from a shared source of truth, or add a `description` field to the status type. At minimum, add a fallback for unknown statuses.
*Command*: `$impeccable clarify`

**[P2] No batch/bulk decision capability**
 evaluators processing many submissions must click through one at a time. The queue page shows 100 pending items — at 30 seconds each, that's 50 minutes of repetitive clicking.
*Fix*: Add multi-select checkboxes to the queue table and a bulk "Verify selected" action (with confirmation dialog).
*Command*: `$impeccable adapt`

**[P3] Sidebar CSS uses variable refs instead of Tailwind utilities**
`evaluator.css` line 5 uses `var(--line)`, `var(--card)` directly instead of Tailwind semantic tokens. While functional, it's inconsistent with the rest of the evaluator which uses `border-border`, `bg-card`, etc.
*Fix*: Replace CSS variable refs with Tailwind utility classes where possible, or document why the CSS approach is intentional.
*Command*: `$impeccable polish`

**[P3] "OEC" acronym never expanded**
The abbreviation "OEC" appears throughout (OEC number, Employment & OEC Details) but is never defined. First-time evaluators may not know it means "Overseas Employment Certificate."
*Fix*: Add a subtle expansion on first use, e.g., "OEC number (Overseas Employment Certificate)" in the detail page heading, or a glossary tooltip.
*Command*: `$impeccable clarify`
