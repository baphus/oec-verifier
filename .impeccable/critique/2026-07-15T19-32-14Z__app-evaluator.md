## What's Working

1. **Queue-first flow with next-pending CTA and closure card** — the entire review loop is coherent: land on pending → decide → next pending → queue clear. This is the single strongest design decision.
2. **Login split layout** — premium feel without decoration; navy gradient with drop-in photo slot is a smart default; form side is clean and well-spaced.
3. **"Evaluated on/by" columns** — adds accountability and audit trail directly in the table without extra clicks; the detail page Decision Record echoes this.
4. **Full semantic token compliance** — zero raw hex, zero Tailwind palette colors; dark mode works everywhere; detector exits 0.

## Priority Issues

**[P2] Responses table is 9 columns wide — dense on smaller screens** — `ResponseTools.tsx:227`. At `min-w-[1100px]`, the table requires horizontal scroll on any viewport below ~1200px. The "Evaluated on" and "Evaluated by" columns are useful but push the Action column far right. Fix: consider a compact mode or progressive disclosure (show evaluated columns only when status ≠ pending). → `layout`

**[P2] Export field picker has 11 checkboxes with no select-all** — `ResponseTools.tsx:175-187`. Users must click 11 times to select all fields. Fix: add a "Select all / Clear all" toggle above the checkbox group. → `polish`

**[P2] No keyboard shortcuts for rapid review** — `DecisionControls.tsx`. Power evaluators reviewing 50+ submissions must click through each one. Fix: add `V` (verify), `R` (reject with reason), `Esc` (back to queue) shortcuts when the decision panel is focused. → `adapt`

**[P3] Detail page card stack is verbose** — `submissions/[id]/page.tsx:112-315`. Five separate card sections (Personal, Address, Employment, Details, Timeline) each with icon + heading + dl grid. The information is correct but the visual weight is heavy for a review task. Fix: collapse into a single card with tabbed sections or an accordion, or merge Address into Personal. → `distill`

**[P3] No contextual help for status meanings** — evaluators seeing "revoked" for the first time may not know what it implies. Fix: add a small help icon or tooltip next to status badges explaining the state. → `clarify`
